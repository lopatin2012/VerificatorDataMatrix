# DataMatrix Verifier

Верификатор штрих-кода **GS1 DataMatrix** (греддинг по ISO/IEC 15415):
поиск кода на изображении/в камере, декодирование содержимого,
оценка качества нанесения и вывод результатов в удобном интерфейсе.

## Возможности

- **Дашборд «светофор»**: большая сцена с кодом, круглый индикатор качества
  (0–100), вердикт ГОДЕН/БРАК, мини-полосы ключевых параметров.
- **Сцена**: зум, поворот, переключение канала (Цвет/Серый/ИК), heatmap —
  проблемные зоны обводятся цветными контурами прямо на изображении;
  переключатель «Подсветка» скрывает/показывает контуры и heatmap.
- **Вкладка «Дефекты»**: карточки проблем с иконками и рекомендациями;
  кнопка «Показать на коде» приближает проблемную зону.
- **Вкладка «Данные»**: содержимое целиком (разделители GS показаны как
  `[GS]`) + чипы GTIN/SN/... с кнопками «Копировать»; предупреждения
  валидации GS1 (контрольная цифра GTIN/SSCC, длины полей, неизвестные AI). Копирование кладёт в
  буфер **сырой текст с настоящим GS-разделителем `\x1d`** — это штатный
  разделитель полей GS1, нужный для корректного разбора AI переменной длины.
- **Вкладка «Отчет»**: человекочитаемый класс (`4,0 · 22×22 · 160 мкм`),
  пороги `Шкала 4/3/2/1`, копирование отчёта, калибровка по известному X-dim и
  PDF (reportlab). Калибровка явно подписывается, при работе без неё выводится
  предупреждение, а грейды помечаются как оценка, не сертификация.
- **Раздельные статусы**: чтение кода, валидация GS1 и качество печати
  показываются отдельно (в GUI, вебе, CLI и PDF), поэтому «код прочитан»
  больше не путается с «код годен».
- **История**: лента миниатюр последних проверок (цветные рамки ОК/Брак)
  и итоговая строка «Проанализировано: N кодов».
- **Выгрузка в TXT**: кнопка «Экспорт TXT» сохраняет все отсканированные
  коды (по одному в строке, без дублей подряд) в текстовый файл.
- **Веб-история**: полоса миниатюр последних проверок, клик — переход к
  результату; экспорт списка в CSV, TXT и PDF.
- Поиск и локализация DataMatrix в кадре/изображении; если код не найден,
  изображение всё равно показывается с пометкой «Код не найден».
- Декодирование GS1-содержимого через `zxing-cpp`; для повреждённых кодов —
  восстановление сетки модулей и декод через `is_pure`.
- Чтение точечных и инверсных (белых-на-тёмном) DataMatrix: морфологическое
  замыкание точек и пересборка сетки модулей по позиции символа.
- Оценка параметров по ISO 15415 (контраст, отражение, неоднородность сети,
  осевая неоднородность, рост печати, фиксированный шаблон, свободная зона
  и др.) с грейдами 0–4 и общим классом.
- UI на Tkinter (файл + камера), CLI/JSON-режим и веб-сервис; в одном
  изображении находятся и оцениваются **все** DataMatrix-коды.
- Прямоугольные символы ECC200 (например, 12×26) оцениваются по реальному
  шагу модулей, а не по соотношению сторон.

## Установка

Используйте venv из репозитория (`.venv`, Python 3.13). Системный `python`
в PATH **не** указывает на venv, поэтому всегда запускайте явно
`.venv\Scripts\python.exe` (или активируйте venv).

```
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Запуск

GUI:
```
.venv\Scripts\python.exe main.py --gui
```

GUI сразу с файлом (или перетащите файл на `tools\quick_open.bat`):
```
.venv\Scripts\python.exe main.py --gui --file "C:\photos\code.jpg"
```

Быстрый консольный отчёт по файлу (или перетащите файл на
`tools\quick_check.bat`):
```
.venv\Scripts\python.exe main.py --file "C:\photos\code.jpg"
```
Подробнее о лаунчерах — в [tools/README.md](tools/README.md).

Быстрый запуск веб-сервера на localhost (порт 8010, браузер откроется сам,
при занятом порте выберется следующий свободный):
```
tools\quick_web.bat
```

Web-сервис для локальной сети (стандартный запуск):
```
.venv\Scripts\python.exe main.py --web --host 0.0.0.0 --port 8010
# или напрямую
.venv\Scripts\python.exe webapp.py --host 0.0.0.0 --port 8010
```
Порт `8000` на этой машине может быть занят Apache — используйте `8010`
или другой свободный.
В браузере: загрузка файла или перетаскивание изображения, съёмка с камеры
(getUserMedia), поле калибровки (пусто = 10 мкм/px), дашборд с
gauge/вердиктом/дефектами, скачивание PDF-отчёта.
Ответы идут с `Cache-Control: no-store`, поэтому правки в `webui/` сразу
видны после перезапуска сервиса.

Docker (репозиторий собирается в образ web-сервиса, порт 8501):
```
docker build -t dm-verifier .
docker run --rm -p 8501:8501 dm-verifier
```

## Сборка (один exe для пользователя)

Самодостаточный файл `dist\DataMatrixVerifier.exe` — Python и зависимости
внутри, ничего ставить не нужно (GUI, CLI и веб-режим).

```
.venv\Scripts\python.exe -m pip install pyinstaller
.\build.ps1
```

Сборка лёгкая: без torch, поэтому нейросетевой локатор не включается, а всё
остальное (zxing-cpp, OpenCV, отчёты, веб) работает. Готовый exe прикрепляется
к релизам на GitHub с тегом, совпадающим с `version.py`.

Один файл:
```
.venv\Scripts\python.exe main.py --file samples/G4_1.jpg
```

Папка с изображениями (выводятся **все** найденные коды в каждом файле):
```
.venv\Scripts\python.exe main.py --dir samples
```

Машиночитаемый вывод для автоматизации:
```
.venv\Scripts\python.exe main.py --dir samples --json
```
Каждый файл даёт `{file, results:[...]}` (или `{file, error}`); поля результата
совпадают с `/api/analyze`. Код возврата `0` — во всех файлах найден хотя бы
один декодированный код, `1` — был файл без кода/с ошибкой.

### Калибровка

Калибровка (мкм/пиксель) задаётся флагом `--um-per-px`, полем в GUI или полем
«Калибровка» в веб-интерфейсе (точка или запятая — обе принимаются):

```powershell
.venv\Scripts\python.exe main.py --file photo.jpg --um-per-px "8,5"
```

- Пустое поле в GUI/вебе означает **10 мкм/px по умолчанию**. В отчёте это
  явно помечается, а физические размеры и грейды считаются ориентировочными.
- Кнопка **«Калибровать по X-dim...»** пересчитывает мкм/px по паспортной
  размерности символа; выбранное значение сохраняется в
  `%APPDATA%\DataMatrixVerifier\settings.json` (Linux/macOS — в
  `~/.config/DataMatrixVerifier/`).
- X/Y-размерность считается по реальному шагу модулей в исходном изображении.
- В отчёте печатается калибровка, предупреждение при работе без неё и
  дисклеймер «грейды — оценка, не сертификация».

### Статусы

Вместо одного «Валидация: OK» теперь три независимых статуса:

- **Чтение** — декодировался ли код;
- **GS1** — OK / N предупреждений / нет данных;
- **Качество** — ГОДЕН/БРАК по грейду (печать).

В отчёте также выводится `Шкала 4/3/2/1` — фактические пороги, которые
использует приложение. Это не сертификационные пороги ISO, а текущая
реализация (см. «Ограничения»).

## Проверка

```
.venv\Scripts\python.exe main.py --selftest
```
Прогоняет встроенные тесты без внешних файлов: GS1-валидация (включая
GS-разделители и даты), декод синтетического обычного / точечного /
инверсного DataMatrix, а также проверки геометрии (мкм по исходному
изображению, свободная зона) и грейда прямоугольных символов. Используется в CI.

## Структура

- `main.py` — CLI / запуск GUI / web-сервис / `--selftest`.
- `ui.py` — интерфейс Tkinter (калибровка, отчёт с копированием).
- `config.py` — пользовательские настройки (сохранённая калибровка).
- `tools/` — лаунчеры Windows: `quick_open.bat` (GUI по файлу),
  `quick_check.bat` (консольный отчёт по файлу) и `quick_web.bat`
  (веб-сервер с автоподбором порта и открытием браузера).
- `webapp.py` — Flask-сервис (REST: analyze, history, result, history.csv/txt/pdf,
  pdf, version). PDF-файлы пишутся во временный каталог, не под `webui/`.
- `webui/` — фронтенд (HTML/CSS/JS: загрузка, камера, heatmap, дашборд).
- `report.py` — официальный PDF-отчёт (с изображением кода, рамкой вокруг
  кода, таблицами и Unicode-шрифтом); там же сводный отчёт по истории.
- `selftest.py` — встроенные smoke-тесты (GS1 + синтетические обычный,
  точечный и инверсный коды), запуск `main.py --selftest`.
- `.github/workflows/ci.yml` — CI: установка зависимостей и прогон тестов.
- `version.py` — версия приложения.
- `verifier.py` — оркестрация пайплайна и итоговые данные.
- `gs1.py` — разбор GS1 AI.
- `core/detect.py` — поиск символа и построение сетки модулей.
- `core/decode.py` — декодирование (zxing + сетка).
- `core/grade.py` — грейды параметров по ISO 15415.
- `Dockerfile`, `.dockerignore` — сборка web-сервиса в образ (порт 8501).
- `samples/` — тестовые изображения G0–G4/ERROR (локальные, в git не хранятся).

Для ручных прогонов удобно использовать и локальную папку с реальными фото
упаковок (`--dir test_image_codes`), если она есть рядом с репозиторием.

## Ограничения

- Грейды приблизительные (не повторяют калибровку эталонного Axicon).
- Без заданной калибровки (по умолчанию 10 мкм/px) физические размеры,
  апертура и грейды ориентировочные — приложение явно это показывает.
- Для точечных и инверсных кодов грейды грубее: яркости инвертируются, а
  распознавание идёт через отдельный fallback.

## Нейросетевой локатор (дополнительно)

Модель ResNet18 (pretrained) с головой регрессии 4 углов, обучена на
`shortery/dm-codes` (300 изображений, лицензия MIT) на RTX 5070 Ti
(данные: `training/train.py`, оценка: `training/evaluate.py`).
Итог: средняя ошибка углов ~168 px при исходном разрешении, область кода
накрывается в 96% случаев.

- Веса: `models/dm_corners.pth` (обучаются в `training/`).
- Инференс: `core/nn_locator.py` (torch, lazy-import).
- Используется как **последний fallback-локатор** в `core/decode.py`:
  NN находит область → вырезается кроп с запасом → по кропу работает
  классический пайплайн (zxing + сетка модулей).
- Если torch не установлен — локатор просто пропускается (приложение
  работает без него).
- Замечание: модель обучалась на «тёмный-на-светлом» фото кодов;
  инверсные (белые-на-тёмном) коды она не локализует — их находит отдельный
  fallback для точечных кодов в `core/decode.py`.
